送料の関数を変えると、どこに響く？

架空のECの送料関数 shipping_fee から、呼び出し元と仕様書を逆向きにたどった実行結果です。このページは保存した結果を読むだけで、ブラウザーではGraphifyを動かしません。

  • 影響探索は公式コードを実行
  • 関係の入力：コードは独自AST、仕様書は手動対応

起点の shipping_fee を除く5ノードが、深さ3までの逆向き探索で見つかりました。

選んだノード

図の内容：仕様書2つ（注文確定仕様・事前見積もり仕様）が、それぞれ関数 checkout_total と delivery_estimate を手動の対応で指し、その2つの関数が shipping_fee を呼び出している。送料仕様 shipping-policy.md は shipping_fee を手動の対応で指す。shipping_fee から逆にたどると、深さ1で3件、深さ2で2件、合計5件が影響範囲になる。

送料無料の基準を 4,000円 → 5,000円 に変えるとき

変える場所は fixture/shipping.py 1行目の FREE_SHIPPING_YEN = 4000。その前に、いまの動きと、確認すべき場所をそろえておきます。

確認する5か所（影響探索の結果）

    変更案は説明のためのもので、コードは変えておらず、変更後の金額も実行・計算していません。影響探索はグラフに入っている関係だけをたどります。グラフにない呼び出し元・画面・テスト・メール文面などは出てこないので、これで全部とは言えません。

    実行したこと・していないこと

    実行した上流の graphify/affected.py の load_graph・resolve_seed・affected_nodes・format_affected（起点 shipping_fee、深さ3）。fixture の Python 関数（3,999・4,000・5,000円）。
    関係の作り方呼び出し2本：run.py の独自アダプター（Python標準ライブラリ ast）。参照3本：run.py に人が書いた対応表。
    実行していないGraphify のCLI、tree-sitter による抽出、LLMによる意味の抽出、MCPサーバー、graphify install・設定・フックの書き込み。
    このページ保存した outputs/result.json と outputs/graph.json を読み、数が6・5・5と合うかを確かめてから描くだけ。ブラウザーでは何も実行しません。

    使いどころ

    日本の受託開発で、送料改定のときにコードと仕様書の確認漏れを減らす。 送料の関数を変えると、注文合計・見積もり表示のコードだけでなく、お客さまと合意した仕様書の記述も直す必要があります。関数と仕様書を同じグラフに入れておけば、「この関数を変えたら、どの仕様書を開くか」を一覧にできます。

    仕様書との対応は、この作例では人が書きました。実際に使うなら、対応表を誰がいつ更新するかも決めておく必要があります。影響の取りこぼしがないことは保証できません。

    保存したファイル

    • outputs/result.json：影響探索の結果・範囲・fixture の実行結果（実行時に書かれたもの）
    • outputs/graph.json：入力にしたグラフ（6ノード・5エッジ）
    • outputs/affected.txt：format_affected の出力
    • run.py：独自ASTアダプター・手動の対応表・公式関数の呼び出し
    • fixture：shipping.py・checkout.py・estimate.py・shipping-policy.md・checkout-spec.md・estimate-spec.md
    • vendor/graphify/graphify/affected.py：実行した上流のコード
    • README.md・request.txt・samples.json
