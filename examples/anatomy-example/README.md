# トークンバケットの卓上装置（Anatomy の作例）

APIのレート制限で使うトークンバケット（容量8・初期8・毎秒2枚の補充）を、Anatomy スキルの方法で「卓上の装置」として描いた操作できる図と、無音24秒の解説動画のソースです。

**API制限の説明モデルです。実際のAPIには接続しません。** ページ・動画・`build.mjs` はどれもネットワークを使いません（ローカルのHTTPサーバーで開く前提。`file://` ではESモジュールと `fetch` が動きません）。

## Opus執筆時点の確認状態

この README を書いた時点（Claude Opus 5.5、`claude-opus-5-5`）では、ブラウザーでの表示・操作・スクリーンショット、`node build.mjs`、動画の書き出しはどれも実行していません。上流 Anatomy の `audit`・`capture`・`lines` の確認スクリプトはこのフォルダーに同梱されておらず、実行していません。表示と動画の確認は親工程（制作担当）が行います。

## モデル（model.mjs）

- 容量 `CAPACITY = 8`、初期 `INITIAL = 8`、補充 `REFILL_PER_SECOND = 2`。
- `request(state)`：1枚以上あれば1枚使って `accepted + 1`、0枚なら `refused + 1`。
- `advance(state, seconds)`：整数秒だけ進め、`min(容量 − 現在, 2 × 秒)` 枚を足す。満タンなら0枚。
- 状態は凍結オブジェクトで、操作は新しい状態を返します。直前の操作は `last`（`accept`・`refuse`・`refill`、補充なら `added` と `before`）に残ります。
- タイマー・乱数・通信は使いません。

### 図と数字が食い違わないための約束

- ページも動画も、`displayState({...state, progress})` の1つの状態から、筒の中の枚数・台座の窓の数字・右下の読み取り値・下の数字・説明文を作ります。
- リクエストは一瞬の出来事として扱い、押し出された1枚は「もう数えない」トークン（縁が朱）として受け箱へ流れます。筒に残る枚数は最初から新しい値です。
- 補充は「1秒の経過」を表すので、台車が運んでいる間（`progress < 0.58`）は前の値を表示し、トークンが積み重なった瞬間に新しい値へ変わります。

## 装置の設計（Anatomy の手順に沿って）

SKILL.md の手順 1〜9 に従いました。

1. **大きさ**：Figure（1つの機構、40〜80部品、SVGのみ・WebGLなし）。
2. **真実**：数はすべて `model.mjs` から。動き・読み取り値・説明文は同じ状態から出す。
3. **物**：縦の収納筒に真鍮の角トークンを積み、手前の押し棒が一番下の1枚だけをゲートから押し出す自動販売機のような装置。奥の補給箱から台車が1秒ごとに2枚を運んで上から落とす。**押し棒の1往復＝リクエスト1件、筒の中の枚数＝あと何件通せるか、台車の1往復＝1秒の補充**。
4. **部品表**（最大71個の立体。`figure.mjs` の `PART_GROUPS` と同じ）

| まとまり | 部品 | 数 |
|---|---|---|
| 台 | 台板、角脚4（座＋脚で8）、手前の定規帯、銘板 | 11 |
| 門型 | 台座フランジ、支柱、補強リブ、片持ちの梁、レール、前後の止め | 7 |
| 補給箱 | 本体（覗き窓つき）、上縁、口に見えるトークン | 3 |
| 押し出しシリンダー | 架台、端板、本体、グランド、押し棒、押し板 | 6 |
| 収納筒 | 台座（数字の窓つき）、角アングル8（±x側は下に1枚分の通り口）、上枠4 | 13 |
| トークン | 真鍮の角トークン（18×18×4、間隔4.6）最大8 | 8 |
| 送り出しゲート | 左右のほお板、まぐさ、旗の受け、拒否の旗 | 5 |
| 滑り台と受け箱 | 脚2、滑り板、左右のレール、受け箱 | 6 |
| 補充台車 | 軸受2、台車板、受け皿の側板2・縁2・天板、吊り具、腕 | 10 |
| 台車で運ぶトークン | 2 | 2 |

細部：台板の溝と四隅のねじ、定規の目盛り（4単位ごと、5本ごとに長い目盛り、帯の縁から生える）、銘板の3本の罫（印字の代わり、`free`）、各板のねじ点、支柱・補給箱・シリンダーの胴の継ぎ目（`sideSeam` を `inner` に）、補給箱の覗き窓（閉じた輪郭、在庫の縁の線は窓の輪郭の端から端まで）、受け箱の口と奥の内壁（口の形で切り抜き）、トークン上面の内側の溝と刻印の点。

5. **座標と視点**（世界座標は約1単位＝図の1px、x・y が台の上、z が上）

| 名前 | 値 |
|---|---|
| 台板 | x −74〜92、y −96〜36、厚さ9、脚6 |
| 台座（筒の底） | 32×32、上面 z = 12 |
| トークン | 18×18×4、積み間隔 4.6。i段目の下面 z = 12 + 4.6i（8段目の上面 48.8） |
| 角アングル | 内面 ±9.2、厚さ1.4、上端 z = 58。±x側は z = 17 から上（下に1枚分の通り口） |
| 上枠 | z 58〜61 |
| ゲート | x 10.6〜13.6、通り口の高さ z 12〜17（1枚分） |
| 押し板 | 待機 x −14.4、押し切り x 8.8（行程 23.2） |
| 滑り台・受け箱 | 滑り板 x 16〜46（上面 z 12）、受け箱 x 47〜75（上面 z 10.4） |
| 補給箱 | 中心 y −47、上縁 z 55 |
| 梁とレール | x −40〜−28、y −86〜14、梁の上面 z 86、レール上面 88.4 |
| 台車 | 待機 y −47（補給箱の上）、落とす位置 y 0（筒の真上）。受け皿の下面 z 65 |

視点は方位角38°（流れの向き x を右下へ長く見せる）、仰角30°（既定）。`fitProjection` で縦横それぞれの枠に合わせます（ページ 600×470、動画の縦 700×700、横 800×660）。

6. **幾何は一度だけ**：静的な部品は投影ごとに1回作ってキャッシュし、毎フレーム作り直すのは押し棒・押し板（長さが変わる）、旗（高さが変わる）、トークン、台車だけです。
7. **描く順番**（奥から手前、下から上）：台 → 支柱 → 奥の軸受 → 梁・レール → 補給箱 → シリンダー → 台座・数字 → 筒の奥側のアングルと上枠 → 押し棒 → 滑り台・受け箱 → 送り出し中のトークン・積んだトークン・落下中（上枠より下）のトークン → 筒の手前側のアングルと上枠 → ゲート・旗 → 手前のレール → 台車（受け皿の奥の板 → 皿の中のトークン → 手前の板 → 天板 → 吊り具 → 腕）→ 前の止め。筒を囲むアングルは奥と手前に分け、トークンをその間に描きます（craft.md の「包む部品は分ける」）。
8. **額**：上流の `.iso-plate` の四隅に「図1」・題・操作のヒント・読み取り値。凡例と説明文はカードの下。図の中の文字は台座の窓の数字（機械が表示する文字）だけ。
9. **動き**：ボタンが目標を決め、時間に沿ったなめらかな動き（smoothstep）。動きを減らす設定では動かさずに結果だけを描きます。押されたら列に入り、順番に1件ずつ動きます。

### 前提と、守れていないかもしれないこと

- 丸い部品・管・ケーブルは使っていません（すべて `slabOf` の角柱）。そのため上流の `kit/audit.mjs` による幾何の監査は要件ではありませんが、**監査も `scripts/lines.mjs` の線端チェックも実行していません**（このフォルダーにはスクリプトを同梱していません）。
- 描く順番は手で決めています。押し出し中のトークンがゲートのまぐさの下を通る一瞬や、補充中のトークンが受け皿の奥の板に近い一瞬は、重なりの前後が厳密でない可能性があります。
- 押し出しの間、上の段は押されているトークンと押し板の上に乗っているとして1段分持ち上げて描き、押し板が戻ると1段落ちます。
- 色は Anatomy の原則（ほぼ単色・1つの強調）に、数える対象である真鍮と、拒否の旗の朱を加えています。

## 動画（video/）

- `window.motionConfig = {duration: 24, fps: 30, width: 720, height: 1280, posterTime: 12, audioEvents: []}`。`window.renderConfig` の `width`・`height`・`fps` があればそれを使います。横長なら横の配置に切り替えます（縦を縮めたり切り取ったりしません）。
- `window.motionReady` はフォントの準備と `../figure.css` の読み込みが終わると解決します。
- `window.seek(t)` は台本（`EVENTS`）を t まで `model.mjs` で適用した状態を作り、同じ `renderFigure` の単体SVGを画像にして canvas に描き、数字・場面名・リクエストの札・時間の帯を重ねます。DOM のスクリーンショットではありません。
- 書き出し時（`window.__MOTION_RENDER__` または `?render`）は操作欄を出さず、`requestAnimationFrame` も使いません。

| 秒 | 場面 | 操作 |
|---|---|---|
| 0 | 満タン：8枚 | なし |
| 2〜6.55 | 8件まとめて → 8件とも通過 | 0.65秒ごとに request ×8 |
| 8.4 | 9件目：0枚なので拒否 | request（拒否・旗が上がる） |
| 10.6〜13.2 | 1秒たつと2枚だけ補充 | advance(1)（12.1秒ごろ着地して数字が変わる） |
| 14.0・15.0 | 補充した2枚で2件通過 | request ×2 |
| 16.8 | 次の1件はまた拒否 | request（拒否） |
| 19〜24 | まとめ（許可10・拒否2・1秒） | なし |
